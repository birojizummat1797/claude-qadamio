## 4. Filter logic (D3)

### 4.2 Holat filtri — faqat mavjud ma’lumot

| Holat | Qoida | Natija | Izoh qatori |
|---|---|---|---|
| Hammasi (default) | filtr yo‘q | 25 | — |

| O‘smoqchiman | **avval “Hozirgi sohangiz qaysi?” → klaster tanlanadi**, keyin faqat shu klaster | klasterga qarab (2–4) | “O‘sish yo‘li hozirgi sohangiz ichida ko‘rsatiladi.” Boshqa sohalar — bitta havola orqali (“Boshqa sohalarni ham ko‘rish”) |

**O‘smoqchiman — egasi qarori (2026-10-03).** O‘sishni xohlagan odamga boshqa sohadagi kasb taklif qilinmaydi (masalan, SMM mutaxassisiga butunlay boshqa yo‘nalish). Shuning uchun:
- Holat tanlanganda klaster filtri majburiy bo‘ladi: “Hozirgi sohangiz qaysi?”. Klaster tanlanmaguncha kartochkalar o‘rnida shu savol turadi.
- Klaster ichidagi barcha kasblar ko‘rsatiladi (`entry` ham): SMM’dagi odam Marketing ichidagi qo‘shni yo‘llarni ko‘radi.
- Bu faqat mavjud `cluster` maydonidan foydalanadi. Yangi qoida yoki qo‘shnilik xaritasi o‘ylab topilmaydi.
- Cheklov: katalog odamning hozirgi kasbini bilmaydi. Shaxsiy “o‘sish yo‘li” — bot/backend ishi (BL-10).

### 4.3 Qo‘shimcha qoidalar
- Tartib: backend klaster tartibi → klaster ichidagi backend tartibi. “Mosroq birinchi” saralash **yo‘q**.

## 5. API / snapshot data contract

### 5.1 Web tomondagi tur (`lib/careers.ts`)

```ts
type PathwayType = "entry" | "role" | "advanced";

interface CatalogCareer {
  slug: string;                 // /^[a-z0-9_]{2,40}$/
  title: string;                // title_uz
  cluster: string;              // backend kaliti, masalan "software"
  clusterTitle: string;         // cluster_uz
  learningMonths: number | null;// butun son 1..36, aks holda null
  pathway: PathwayType | null;  // noma’lum qiymat → null
  signals: SignalKey[];         // ≤3, tartiblangan, VAZNSIZ
  status: "active";
}

interface PlannedCareer {
  id: string;                   // web ichki id, backend slug emas
  title: string;
  status: "planned";
}

interface CareerCatalog {
  taxonomyVersion: string;      // "v2.2"
  source: "api" | "snapshot";
  generatedAt: string;          // ISO sana
  careers: CatalogCareer[];
  planned: PlannedCareer[];
}
```

### 5.2 Ma’lumot oqimi

```
backend taxonomy_v1.json / GET /api/v1/taxonomy
        │  scripts/sync-careers.mjs (qo‘lda ishga tushiriladi)
        │  vaznlar → top-3 signal kaliti, maosh/prerequisites tashlanadi
        ▼
content/careers.snapshot.json  (repo’da, taxonomyVersion bilan)
        │
build ──┼── QADAM_API_URL bor → GET /api/v1/taxonomy/careers (timeout 5s, ISR 24h)
        │      javob validatsiyadan o‘tsa → nom/klaster/oy/yo‘l API’dan,
        │      signallar snapshot’dan (slug bo‘yicha)
        └── API yo‘q / xato / validatsiyadan o‘tmadi → to‘liq snapshot
```

Qoidalar:
- Build hech qachon API’ga bog‘liq emas (CI’da tarmoq yo‘q). Snapshot doim bor.
- API’dagi `version` snapshot’dagi `taxonomyVersion` dan farq qilsa, signallar **yashiriladi** (eskirgan signalni yangi kasbga yopishtirmaymiz). Qolgan maydonlar API’dan ko‘rsatiladi.
- API’da bor, snapshot’da yo‘q kasb → signalsiz ko‘rsatiladi.
- Yaroqsiz yozuv (slug regex’dan o‘tmaydi, nom bo‘sh) → tashlab yuboriladi va build log’ga yoziladi.
- Snapshot’da `salary`, `weight`, `signals` obyekt ko‘rinishi, `prerequisites` kalitlari bo‘lmaydi (testda tekshiriladi).

### 5.3 Backend tomoni (ochiq savol Q3)
- **Hozir (B3):** backend’ga tegmaymiz. Signal kalitlari sync skripti orqali olinadi.
- **Tavsiya (backlog BL-7):** `/api/v1/taxonomy/careers` ga `display_signals: string[]` (vaznsiz) qo‘shish. `GET /api/v1/taxonomy` dan vazn va maoshni public’dan olib tashlash (audit §9.6). Bu backend o‘zgarishi — alohida ruxsat bilan.

## 7. Test plan

### Unit (Vitest)
1. Snapshot sxemasi: 25 active, har bir slug unikal va regex’ga mos, `taxonomyVersion` bor.
2. Snapshot’da taqiqlangan kalitlar yo‘q: `salary*`, `weight*`, `prerequisites`, signal obyektlari (faqat string massiv).
3. Signal tanlash: ≤3, faqat ≥4 vazn, teng vaznda kanonik tartib. Sync skripti fixture bilan tekshiriladi.
4. Signal iboralari: 13 backend kaliti ↔ 13 ibora (ortiqcha ham, kam ham emas); iboralarda raqam, `%`, taqiqlangan so‘zlar yo‘q.
5. Pathway mapping: 3 qiymat + noma’lum → `null`; UI matnida `entry/role/advanced` yo‘q.
6. Filtr funksiyasi: Hammasi = 25, Boshlayapman = 8, Almashtiraman = 25, O‘smoqchiman klastersiz = 0 kartochka + “Hozirgi sohangiz qaysi?”, klaster bilan = faqat shu klaster; klaster × holat kombinatsiyalari; bo‘sh natija (`data_ai` + boshlayapman = 0).
7. API adapter: timeout → snapshot; noto‘g‘ri JSON → snapshot; version farqi → signallar yashirin; noma’lum `pathway_type` → `null`.
8. Deep link: `w1-ct-<slug>`, `w2-ct-<state>-<slug>`, hammasi `START_PAYLOAD_RE` ga mos va ≤64 belgi.
9. Planned: Telegram URL yasalmaydi; nom active ro‘yxatda takrorlanmaydi.
10. Katalog copy’sida maosh, foiz, “siz uchun”, uydirma statistika yo‘q.
